## A. Mass effect stored exactly like a one-target effect

**What the engine does.** `extract_target_filter_from_effect` (`crates/phase-ast/src/types/ability.rs`) returns the effect's `Typed` filter, because a `Typed` filter is not a context ref. Its carve-outs are `Sacrifice`, `UnattachAll`, `Bounce` at resolution and `PairWith`, among others. Only one carve-out covers phasing: `phase_out_or_in_filter_is_mass`, added for #2907. It accepts exactly `Typed[Permanent]` with a controller and no properties, or a target-player population. `Regenerate` has none.

`collect_target_slots_inner` (`crates/engine/src/game/ability_utils.rs`, generic branch) then pushes one required slot. It errors "No legal targets available" when the slot is empty.

- `regenerate::resolve` (`crates/engine/src/game/effects/regenerate.rs`) shields only `ability.targets` when targets exist.
- `phase_out::collect_object_targets` returns the declared targets before its mass fallback.

So a "Regenerate each …" asks for one target, regenerates only it, and can't be cast with no creatures. Measured: Wrap in Vigor then "Destroy all creatures" leaves the targeted bear on the battlefield and the other in the graveyard. A "… all [non-Permanent filter] phase out" also asks for one target. Measured: Taniwha's upkeep trigger phases out one of three lands.

`PutChosenCounter` is different. It isn't stack-targeted at `Resolution` timing, and its resolver (`put_chosen_counter.rs`, `resolved_counter_targets` → `targeting::resolved_object_ids_for_filter_with_context`) expands a `Typed` filter over the battlefield. Phase's own test asserts every other creature gets the counter.

## C. An object chosen, not targeted, typed as a target

This is **not #10688's root cause.** #10688 ("Choose-then-act follow-ups: the later clause binds the wrong object") is about the follow-up clause that names the chosen object.

The choice-as-target half was handled by #10176 (closed) and merged PR #10555. That PR gives a bare "Choose a … you control." sentence `Resolution` timing, and returns four shapes to `Stack` on purpose. Two of the candidates are among them: Crush Underfoot and Guard Dogs ("the antecedent of a later printed target").

What PR #10555 doesn't reach is the same untargeted object written inside another instruction:

- "transform an Incubator token you control" (`Transform { scope: Single }`);
- "a copy of a nonlegendary enchantment you control" (`CopyTokenOf` with no `source_filter`).

`Effect::target_filter` exposes both, so they get a stack slot. That is staged as issue 02.

`TurnFaceUp` exposes no filter, so Bustle and Zimone are unaffected.
